# Implementation Plan: Monthly Summary View

## Goal

Add a "Monthly Summary View" to the existing vanilla-JS Expense & Budget Visualizer: a new `<section>` in `index.html` (after the chart section) that groups spending by calendar month, showing each month's total and a per-category (Food/Transport/Fun) breakdown, newest month first, with a friendly empty state. Business logic goes in `TransactionManager`; rendering goes in a new `MonthlySummaryComponent`; both are wired through `UIManager.refreshAll()` so the view stays live on add/delete and multi-tab storage sync.

## Hard constraints (from the task — do not violate)

- Work directly in the workspace. No worktree, no git branch required by this task.
- Exactly ONE JS file (`js/app.js`) and ONE CSS file (`css/styles.css`). Do NOT add a second JS or CSS file.
- Do NOT modify anything under `.kiro/specs/`.
- Do NOT add dependencies. Chart.js 4.x stays the only external lib (CDN).
- No inline styles set from JS (`element.style.*`). Toggle CSS classes instead (use the existing `is-hidden` utility + `getElementById` + `classList`), exactly like the existing components.
- No embedded JS in HTML, no JS in CSS. camelCase JS. Comment any function over ~10 lines or with non-obvious logic (JSDoc on methods, matching the existing style).

## Grounding: exact symbols already in the code (match these)

- Currency: module-level `formatCurrency(cents)` in `js/app.js` (returns `"$1,234.56"`, handles overflow/NaN). REUSE it; do not write a new formatter.
- Categories source of truth: `TransactionManager.CATEGORIES` = `['Food', 'Transport', 'Fun']`. Iterate this; never hardcode category strings.
- Transaction shape: `{ id, itemName, amount (integer cents, >=0), category, timestamp (Unix ms) }`.
- Defensive amount guard used by `getTotalCents()` and `getCategoryTotals()`: skip amounts where `!Number.isInteger(amount) || amount < 0` (equivalently include only `Number.isInteger(amount) && amount >= 0`). Use this SAME guard in the new aggregation.
- Newest-first ordering: existing list sorts by `b.timestamp - a.timestamp`. Months must sort newest-first too.
- Empty-state pattern: an element toggled by adding/removing the `is-hidden` utility class (`.is-hidden { display: none !important; }`), driven via `classList` — see `TransactionListComponent.showEmptyState()` / `hideEmptyState()` which operate on `this.emptyState` (the `#empty-state` element). The new empty state must mirror this.
- Component style: constructor caches DOM refs via `document.getElementById(...)` with defensive null-guards (`if (!this.container) return;`), small JSDoc'd methods, DOM built with `document.createElement` + `DocumentFragment` and `textContent` (never `innerHTML` concatenation of transaction data) — see `TransactionListComponent.createTransactionElement()` / `render()` / `clearItems()`.
- Category color classes already in CSS: `.category-Food`, `.category-Transport`, `.category-Fun` (backed by vars `--color-food`, `--color-transport`, `--color-fun`). The transaction category badge uses class `transaction-category category-${category}`. Reuse this `category-${category}` convention for the per-category breakdown chips.
- CSS custom properties to reuse: spacing `--spacing-xs/sm/md/lg/xl` (8px base scale), colors `--color-text`, `--color-text-secondary`, `--color-background`, `--color-background-alt`, `--color-border`, shadows `--shadow-sm`/`--shadow-md`. The `[data-theme="dark"]` block overrides these same tokens, so referencing the tokens (never hardcoded hex) makes the new CSS work in both themes automatically. Do NOT hardcode colors.
- Section styling precedent: the chart section is styled via the attribute selector `section[aria-label="Spending distribution chart"]` (background `--color-background-alt`, `padding: var(--spacing-lg)`, `border-radius: 8px`, `box-shadow: var(--shadow-sm)`). The transaction card uses `.transaction-item` (flex, border, radius, shadow, hover lift). Match these for visual consistency.
- `UIManager.initialize()` instantiates components: `this.inputForm = new InputFormComponent('transaction-form')`, `this.transactionList = new TransactionListComponent('transactions-container')`, `this.balanceDisplay = new BalanceDisplayComponent('balance-amount')`, `this.chartComponent = new ChartComponent('expense-chart')`, then calls `this.refreshAll()`.
- `UIManager.refreshAll()` reads data once (`getTransactions()`, `getTotalCents()`, `getCategoryTotals()`), renders list+balance inside a `requestAnimationFrame(...)` callback, and runs the chart via `this.debouncedChartUpdate(...)`. The monthly summary render must be added here.
- Multi-tab sync path: a module-scoped `window.addEventListener('storage', ...)` calls `uiManager.handleStorageChange(event)`, which calls `this.transactionManager.initialize()` then `this.refreshAll()`. Because the summary renders from `refreshAll()`, wiring it there gives add/delete AND multi-tab sync updates for free — no extra listener needed.

## Design decisions (made here; one rationale each)

1. Monthly grouping key is `"YYYY-MM"` derived from LOCAL time (not UTC), because display labels and user expectation are local-time based; computed from the `Date` object's local getters so the key and the label agree. Rationale: the task mandates local-time grouping and a `"YYYY-MM"` internal key.
2. Human label via `Intl.DateTimeFormat('en-US', { year: 'numeric', month: 'long' })` (e.g. "October 2026"), matching the app's existing `en-US` usage in `formatCurrency` (`Intl.NumberFormat('en-US', ...)`). Rationale: consistency with the one locale the app already pins.
3. `getMonthlySummaries()` returns, per month, a `categoryTotals` array built by iterating `TransactionManager.CATEGORIES` (always all three categories, in canonical order, even when zero), mirroring how `getCategoryTotals()` always emits every category. Rationale: stable, complete shape for the view; matches existing precedent.
4. The component renders each month as a card (reusing the `.transaction-item`-style card look) containing the month label, the month total via `formatCurrency`, and three category chips reusing `category-${category}` color classes. Rationale: visual match with the transaction list the task asks for, no new color system.
5. Empty state is a single `<p>` inside the summary container, toggled with `is-hidden`, exactly like `#empty-state`. Rationale: the task requires mirroring the existing empty-state/hidden-class pattern.

## Steps

- [ ] 1. Add `getMonthlySummaries()` to `TransactionManager` (business logic lives in the manager, not the view).
      What: Add a JSDoc'd method on `TransactionManager` that aggregates `this.transactions` into monthly summaries. For each transaction, apply the SAME guard as `getTotalCents()`/`getCategoryTotals()` (skip when `!Number.isInteger(transaction.amount) || transaction.amount < 0`); also skip when the category is not in `TransactionManager.CATEGORIES`. Derive the local-time month key `"YYYY-MM"` from `new Date(transaction.timestamp)` using local getters (`getFullYear()`, `getMonth() + 1` zero-padded). Accumulate per-month `totalCents` and a per-category cents map seeded to 0 for every `TransactionManager.CATEGORIES` entry (same seeding idea as `getCategoryTotals`). Build the human label with `new Intl.DateTimeFormat('en-US', { year: 'numeric', month: 'long' }).format(...)` using a Date at day 1 of that month. Return an array of `{ monthKey, label, totalCents, categoryTotals: [{ category, totalCents }, ...] }` sorted newest-first by `monthKey` descending (string compare works for `"YYYY-MM"`). Add explanatory comments (method exceeds ~10 lines).

## Priority guidance (if difficulties arise)

Favor the simplest working approach over a perfect one. The non-negotiable core is: cents-based math via `formatCurrency`, one JS file + one CSS file, no inline styles set from JS (toggle classes), and live updates via `UIManager.refreshAll()`. If any step gets stuck, it is acceptable to drop nice-to-haves to land a working, verified result — specifically: the responsive `@media` tweak in step 5 is optional, and the per-category chip breakdown can be simplified (or, as a last resort, reduced to just the month label + month total) rather than blocking the feature. Do not get stuck polishing styling. Steps 1-4, 6 and the core of step 5 are the must-haves.

## Notes / assumptions

- Heading text ("Monthly Summary"), the empty-state wording, and the exact chip label format are not dictated by the spec; the plan picks sensible, convention-matching values. The coder may adjust wording as long as it stays consistent with existing copy.
- No automated test framework exists in this repo (no `package.json`, no test runner), and the README states there is no build step, so verification is manual browser/DOM testing by design — this is the project's real "test command."
- Local-time month boundaries are intentional (per the task). A transaction near a month boundary is grouped by the user's local calendar month, consistent with the label shown.
